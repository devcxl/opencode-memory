## 2. M1 详细设计：缓存隔离与字符预算

### 2.1 SystemPart 分层与会话冻结快照

当前 `apps/plugin/src/index.ts`（L101-122）将 `memoryContext + instructions + reminder` 拼成单个文本块，每次请求都重新 `readFile`。演进后拆分为最多 3 个有序 `SystemPart`：

```text
event.system.push(
  Part 1: { type: "text", text: staticInstructions },      // 静态：memory-awareness.md 或 BOOTSTRAP_INSTRUCTIONS
  Part 2: { type: "text", text: frozenMemoryContext },     // 会话冻结：# Memory Context (...)
  Part 3: { type: "text", text: dynamicReminder }          // 动态尾部（仅需要时 push）：## Memory Reminder
)
```

**冻结与失效策略（`SessionContextCache`）**：

- 缓存键：`sessionID`（在 `session.deleted` 时清理，避免内存泄漏）。
- **命中**：同一会话后续轮次直接返回缓存的 `frozenMemoryContext`，保证发送给 LLM Provider 的前缀字节严格稳定。
- **精准失效条件**：
  1. 本 `sessionID` 在 `ctx.tool.hook("execute.after")` 中**成功**执行了 `write` / `edit` / `delete`，且 `target` 属于会注入上下文的文件（`memory` / `identity` / `user` / `bootstrap`）。
     - **关键优化**：`target === "daily"` 写入成功**不**失效快照，因为 `daily` 不进入 `buildContext()`，从而保护长会话写日常日志时的 KV Cache。
  2. 收到 `compaction` 钩子或引导状态变化（`BOOTSTRAP.md` 被创建/删除）。
  3. 超过可选兜底 TTL 或用户显式执行 `/memory-consolidate`。

### 2.2 字符预算与占用率反馈

沿用 Hermes 已被验证的“预算即纪律”设计，但结合编码多项目场景放宽默认值，全部支持在 `opencode.json` `options.limits` 覆盖：

| 目标文件                       | 默认字符上限                                        | 行数安全兜底          | 自动注入 |
| ------------------------------ | --------------------------------------------------- | --------------------- | -------- |
| 全局 `MEMORY.md`               | `6,000` chars                                       | `1,000` lines（保留） | 是       |
| 项目 `projects/<id>/MEMORY.md` | `6,000` chars                                       | `1,000` lines（保留） | 是       |
| `USER.md`                      | `2,500` chars                                       | —                     | 是       |
| `IDENTITY.md`                  | `2,500` chars                                       | —                     | 是       |
| `daily/YYYY-MM-DD.md`          | 不限制注入上限（单次写入仍受 `100KB` payload 限制） | —                     | 否       |

**反馈文案规范（遵循 `b4d7d4f` 低噪声原则）**：

- 正常写入/编辑/删除受限文件时，在结果末尾附加 1 行：
  `Budget: 1,420/6,000 chars (24%)`
- 占用率 ≥ 85% 时附加 1 句：
  `Budget: 5,280/6,000 chars (88%) — near limit, consider consolidating or deleting stale entries.`
- 超过上限时拒绝落盘，并返回当前文件按 `<!-- YYYY-MM-DD HH:MM:SS -->` 切分的条目摘要清单（时间戳 + 前 60 字符预览），方便模型下一步精确删除或替换。

### 2.3 原子腾挪（`replace_timestamps`）

在 `MemoryToolInput`（`apps/plugin/src/tool/schema.ts`）为 `write` action 增加可选字段：

- `replace_timestamps?: string[]`：在同一次 `write` 调用内，先按时间戳移除旧条目，再追加/写入新内容，**只在最终合并文本上校验字符上限**，最后执行一次 `atomicWrite` + `embedAndIndex` + `gitCommit`。
- 不引入复杂的通用事务脚本数组，保持 Schema 精简且向后完全兼容。

## 3. M2 详细设计：Hybrid 检索、衰减与 Provenance

### 3.1 向量检索提速与增量索引（衔接 `#30`, `#31`, `#32`, `#37`）

1. **切片嵌入增强（`#30`）**：`chunkMarkdown()` 生成用于嵌入的文本时拼接文件路径/标题上下文（如 `[projects/xxx/MEMORY.md > Architecture]`），提升短条目语义表征；超长切片按字符上限（如 1200 chars，overlap 150 chars）二次切分。
2. **先 Hash 后 Embedding（`#32`）**：`VectorStore.upsertFile()` 先读取现有索引 items 的 `hash` 集合，仅对**新增或变更**的 chunk 调用 `embedText()`，消除无变更切片的 O(N) ONNX 重复推理。
3. **带栅栏后台队列 + 并发互斥锁（`#34`, `#37`）**：对同一文件路径的写入/索引更新串行化；`search` 读取前等待对应路径的挂起索引任务 flush。

### 3.2 Hybrid 混合检索与排序流水线（升级 `#29`）

在 `FileSearcher` 中保留窄接口设计，形成 5 步纯本地流水线（零 C++ 原生依赖）：

```text
Query
  ├─► [1a] 语义路：embedText(query) → VectorStore.searchGlobal / searchProject (topK * 4)
  ├─► [1b] 词法路：BM25 评分（覆盖 scope 内所有 .md chunk，按精确 token + 驼峰/下划线切词）
  │         └─ 先按 scope 与 period（daily 文件名日期 / chunk timestamp）前置过滤（解决 #31）
  ▼
[2] 分数归一化与反饱和融合：
    - 词法 BM25 rank/score 做反饱和映射（避免高频词压倒语义），默认权重：
      baseScore = 0.70 * vectorScore + 0.30 * lexicalScore
    - 纯词法命中但未入向量候选集时保留 lexical 加权分，保证精确错误码/环境变量可被召回
  ▼
[3] MinScore 阈值过滤（默认 minScore = 0.25，在时间衰减之前执行，防误杀高相关旧笔记）
  ▼
[4] 分层时间衰减（Temporal Decay）：
    - MEMORY.md / USER.md / IDENTITY.md → evergreen（衰减乘子 = 1.0）
    - daily/YYYY-MM-DD.md → 从文件名提取日期计算 ageDays，乘以 exp(-(Math.LN2 / 30) * ageDays)
  ▼
[5] 轻量 MMR 去重（lambda = 0.7）：
    - 基于 chunk token Jaccard 相似度惩罚已选结果，避免同一段日志多个切片霸榜，输出 topK
```

### 3.3 轻量 Provenance（来源标记）

不破坏现有 Markdown 纯文本可读性，复用现有时间戳注释行：

```markdown
<!-- 2026-11-21 14:20:00 -->                      # 向后兼容，默认视为 agent
<!-- 2026-11-21 14:20:00 | origin: owner -->       # 用户明确要求记住的规范/偏好
<!-- 2026-11-21 14:20:00 | origin: external -->    # 来自网页抓取/搜索摘要的外部信息
```

- `timestampParser.ts` 扩展解析可选 `| origin: <value>`，同时保持 `deleteByTimestamp` 按时间戳前缀精确匹配。
- `MemoryToolInput` 增加可选 `origin: z.enum(["owner", "agent", "external"]).optional()`（默认 `"agent"`）。
- **强隔离规则**：
  - `origin === "external"` 写入 `target === "memory"` 时拒绝或自动降级/提示改写到 `daily`；
  - `buildContext()` 构建自动注入内容时，自动过滤掉带 `origin: external` 的条目，从结构上阻断间接提示注入。

## 4. M3 详细设计：OpenCode V2 生命周期闭环

### 4.1 Compaction 前自动沉淀（`ctx.session.hook("compaction")`）

依据 `@opencode/plugin@2.3.0` 类型定义（`dist/promise/session.d.ts` L44-54, L193）：
`SessionCompaction` 继承自 `SessionContext`，包含只读的 `sessionID`、`agent`、`model`、`system`、`messages`、`tools` 与可写的 `result`。

**执行机制**：

1. 在 `SessionStateStore` 中为每个 `sessionID` 维护 `compactionFlushCount` 或最近已沉淀消息游标（保证同一轮压缩周期最多执行一次，防止循环触发）。
2. 当 `ctx.session.hook("compaction", async (event) => ...)` 被调用时：
   - 提取 `event.messages` 中尚未归纳的近期用户/助手轮次文本（裁剪工具冗长输出，控制输入 Token）。
   - 若对话过短（如有效文本 < 500 chars）或本周期已沉淀，直接跳过。
   - 借助 `ctx.experimental.generate.text(...)`（受控超时如 `8000ms`，失败静默降级、**绝不抛错阻塞 compaction**）抽取「本会话新产生且未写入记忆的架构决策、用户偏好、关键排错结论」。
   - 若抽取结果非空（非 `NO_MEMORY` 哨兵），调用 `memoryManager.appendFile()` 写入当前项目（或全局）`daily/YYYY-MM-DD.md`（附带 `origin: agent`），并触发索引更新。
   - 同时向 `event.system` 补充一条轻量说明，告知压缩摘要生成模型「关键结论已持久化至 daily 日志，无需全文背诵细节」。

### 4.2 `/memory-consolidate` 按需蒸馏命令

类似现有的 `registerMemoryInitCommand.ts`（`ctx.command.transform`）：

1. 注册 `/memory-consolidate [days]`（默认回溯最近 `7` 天的项目 `daily/`，无项目上下文时回溯全局 `daily/`）。
2. 命令 `execute` 汇总：
   - 目标 `MEMORY.md` 当前全文与字符预算余量；
   - 最近 N 天的 `daily/` 内容（自动排除 `origin: external` 或标注来源以便模型甄别）；
   - 通过 `ctx.session.prompt(...)` 下发结构化整理 Prompt，引导当前会话模型使用 `memory` 工具（含 `replace_timestamps` / `edit` / `delete`）完成去重、合并与过时条目退休。
3. 每次修改均由 `gitCommit()` 自动留痕，用户可通过 `git diff` / `git revert` 审计或回滚。

## 5. 测试与验证策略

1. **M1 单元测试**：
   - 冻结快照命中与写 `daily` 不失效测试（验证 `buildSystem()` 在写 `daily` 前后返回同一字节、写 `memory` 后立即更新）。
   - 字符预算边界测试、`Budget:` 提示格式、超限拦截与 `replace_timestamps` 原子先删后加测试。
2. **M2 单元测试**：
   - Hybrid 检索对比测试（精确环境变量/报错码命中、BM25+向量合并排序）。
   - 时间衰减测试（验证 `minScore` 在衰减前过滤，且 `MEMORY.md` 不衰减、`daily` 按 30 天半衰期衰减）。
   - Provenance 隔离测试（`origin: external` 不进入 `buildContext()` 自动注入）。
3. **M3 集成测试（基于 `v2-plugin-harness.ts`）**：
   - Mock `compaction` hook 与 `experimental.generate.text`，验证：超时/异常不阻塞压缩、每个压缩周期只 flush 一次、抽取内容正确落入项目 `daily/`。
   - `/memory-consolidate` 命令端到端测试。
