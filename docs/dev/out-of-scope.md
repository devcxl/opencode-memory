# Out of Scope — opencode-memory 双模式架构

> 记录在需求分析中明确排除的功能及原因，避免后续重复讨论。

---

## Phase 2 (本次) 排除项

| # | 排除功能 | 排除原因 | 后续可能 |
|---|---|---|---|
| 1 | 本地 ↔ 远程自动同步（Hybrid 模式） | 实现复杂度极高：冲突解决、增量同步、一致性保证需数周独立工程 | Phase 3 |
| 2 | 离线降级（网络断开自动切本地） | 远程模式下网络不可用即报错，用户需手动切回 local mode。混合模式的先决条件 | Phase 3 |
| 3 | MCP 协议保留 | 用户决策：直调 REST API 更简单直接，少一层协议开销 | 永久排除 |
| 4 | 多用户/团队协作权限 | 当前 JWT 只做单用户认证，无 RBAC 系统，需要独立设计权限模型 | Phase 4 |
| 5 | 记忆数据加密（端到端） | 远程存储的隐私保护需要密钥管理 + 加密方案，复杂度高 | Phase 4 |
| 6 | 本地记忆迁移到远程 | 第一次使用远程时需要手动操作，暂不提供自动导入工具 | Phase 3 |
| 7 | auto-capture（对话自动提取记忆） | 依赖 LLM 后处理，工程量大。当前依赖 AI 主动调 memory tool | Phase 4 |
| 8 | 新的 Web UI 功能 | 保留现有 cloudflare-memory Web UI，不增加新页面/功能 | Phase 4 |
| 9 | Bootstrap 引导阶段扩展（远程） | 当前引导逻辑只针对本地文件模式，远程模式跳过引导 | Phase 3 |
| 10 | 向量索引 staleness 跨后端感知（远程） | Workers AI 模型切换由后端自行管理，客户端不感知 | 后端自行处理 |
| 11 | CI/CD 工作流重建 | 原有的 .github/workflows 不迁移，待 Phase 4 重新配 | Phase 4 |
| 12 | Electron/Desktop 支持 | opencode-memory 当前只支持 CLI/TUI 环境 | 未规划 |
