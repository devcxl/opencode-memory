# v2.1-T2: 分文件字符预算、占用率反馈与单次原子腾挪

## 目标

用分文件字符上限取代单一 1000 行粗限制，在写入反馈中提供低噪声占用率提示，并支持同一次 `write` 调用内先删旧再写新。

## 改动

1. `config/runtime.ts`：支持可选 `options.limits`（默认全局/项目 `MEMORY.md: 6000`、`USER.md: 2500`、`IDENTITY.md: 2500` chars），保留 1000 行安全兜底。
2. `utils/validation.ts`：新增 `checkCharBudget(filePath, content, limits)`；超限时抛错并附带当前文件已有条目的时间戳与前 60 字符摘要列表。
3. `handlers/handleWrite.ts` / `handleEdit.ts` / `handleDelete.ts`：
   - 对受限文件在返回值末尾附加 1 行简洁占用率：`Budget: 1,420/6,000 chars (24%)`（≥85% 附预警提示）。
4. `tool/schema.ts` & `MemoryManager.ts`：
   - 为 `write` action 增加可选 `replace_timestamps?: string[]`，在单次调用内先按时间戳剔除旧条目再拼接新内容，只在终态校验字符预算后执行一次 `atomicWrite` + `embedAndIndex` + `gitCommit`。

## 验收

- 写入 `USER.md` / `IDENTITY.md` / `MEMORY.md` 超出字符预算时明确拦截并列出可清理时间戳。
- 正常写入返回包含 `Budget: x/y chars (z%)`；85% 以上出现预警。
- 使用 `replace_timestamps` 能在接近上限时单次完成“删旧写新”，并触发一次 Git 提交。
