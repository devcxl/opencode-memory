# Proposal: 项目级别记忆隔离

## 动机

当前 opencode-memory 插件的所有记忆（MEMORY.md、daily/）均为全局共享。当用户在不同项目间切换时：

- **上下文污染**：A 项目的架构决策、编码规范注入 B 项目的对话，产生不一致建议
- **搜索噪音**：语义搜索返回无关项目的记忆片段，命中质量下降
- **记忆膨胀**：MEMORY.md 有 1000 行硬限制，多项目共享更快触及上限

需要引入项目级别的记忆隔离，使 AI 能在不同项目中保持项目特有的"肌肉记忆"，同时复用全局人格/身份信息。

## 方案概要

采用**目录隔离**方案（用户已设计稿）：

```
~/.config/opencode/memory/
├── MEMORY.md                ← 全局记忆（跨项目通用偏好、规则）
├── IDENTITY.md              ← 全局 AI 身份（不改动）
├── USER.md                  ← 全局用户画像（不改动）
├── daily/                   ← 全局日志（保留，涵盖所有项目）
└── projects/
    ├── luckyc/
    │   └── MEMORY.md        ← 项目记忆（架构决策、约定、关键路径）
    └── photosync/
        └── MEMORY.md
```

**设计决策**：daily 日志保持全局。daily 本质是跨项目的时间线流水记录，拆分会破坏时序完整性（一天的工作被拆成多个文件），且增加不必要的索引和路由复杂度。

### 核心行为变更

| 维度 | 当前 | 变更后 |
|------|------|--------|
| 上下文注入 | MEMORY + IDENTITY + USER | 上述 + 当前项目 MEMORY（条件注入） |
| 搜索 | 全局 + daily 全搜 | 默认全局+当前项目；支持 `--scope` 参数 |
| 写入 | --target memory → 全局 | 默认全局；可用 `--project` 指定写入项目 |
| daily 归属 | 全局 daily/ | 始终全局 daily/（保持不变） |

### 项目检测策略

1. 优先：`git remote get-url origin` → 提取 `owner/repo` 作为项目标识
2. 回退：当前工作目录名
3. 无项目（不在项目目录中）：回退到当前全局行为（完全兼容）

## 范围

### 包含

- 项目目录结构创建与管理
- 项目自动检测（git remote / cwd）
- 上下文注入：全局文件始终注入 + 项目 MEMORY 条件注入
- 语义搜索分层：支持 `--scope global|project|all`
- Vectra 索引隔离（每个项目独立索引）
- memory 工具新增 `--project` 参数（向后兼容）

### 不包含

- 项目级 IDENTITY/USER（这两个属于全局人格定义）
- 跨项目记忆共享/继承
- UI 配置界面
- 项目自动发现（扫描所有 ~/projects）
- 现有 daily 历史数据迁移（保留在全局目录）

## 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 项目标识不稳定（重命名目录导致记忆丢失） | 高 | git remote 优先；记录映射文件 `.opencode-memory-project` |
| Vectra 索引数量膨胀（每项目 +1 索引） | 中 | 仅 root 索引；懒创建；不建 project daily 索引 |
| 搜索默认行为变更（老用户困惑） | 中 | `--scope all` 兼容旧行为；文档说明 |
| 全局 MEMORY.md 语义迁移 | 低 | 引导用户逐步将项目特定内容迁移到项目 MEMORY |

## 已澄清的问题

- daily 文件保持全局，按自然日期组织，不在 daily 条目中加项目标记
- 项目首次使用时自动创建 `projects/{name}/` 目录结构（仅 MEMORY.md）
- 不在项目目录中时，所有行为与当前完全一致（零破坏性变更）
